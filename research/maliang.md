## 0. 一句话定位

**面向中文网文作者的「云端长篇小说项目管理系统 + 7 Agent 协作写作引擎」**——卖点不是"会写字"，而是把书名/设定/三级大纲/知识图谱/伏笔台账做成结构化资产，让 AI 在第 40 章还记得第 4 章，并顺带把"去 AI 味 + AI 率自检 + 封面/短剧改编"接成一条投稿前流水线。**【官方】**（[首页](https://maliangwriter.com/)、[llms.txt](https://maliangwriter.com/llms.txt)）

一句话对比：**笔灵/蛙蛙卖"一句话出稿"，马良卖"可控的长篇工程"。**（此对比框架出自马良自己的对比页，注意其立场）**【官方】**（[横评页](https://maliangwriter.com/compare/best-ai-for-chinese-web-novel-2026/)）

## 1. 目标用户

**核心人群（官方叙事 + 产品设计共同指向）**

1. **网文日更党 / 签约作者**：番茄、起点、盐选等平台连载，日更 3000–10000 字，卡文、吃书、掉更具象痛点。产品所有"防吃书/保节奏/日更 1 万字"卖点都指向这群人。**【官方】**
2. **长篇连载（20 万字以上）作者**：知识图谱容量、三级大纲、按卷渐进披露、整本一致性体检，全是为"百万字不烂尾"设计的。**【官方】**
3. **同时开多本书的作者**：书架多项目管理、书级绑定文风分身、按书隔离知识图谱。**【官方】**
4. **愿意投入结构、要作品长期运营的人**（"愿意搭大纲"而非"只要产出"的人）。**【官方】**[对比页 vs 笔灵](https://maliangwriter.com/compare/maliang-vs-biling/)
5. **短剧/短篇跨界者**：短篇快写、章节转剧本、盐选/番茄简介模板。**【官方】**

**明确不主打的人群**

- **纯小白想一键全自动**：官方自己承认"AI 是工具不是代笔"，且入门需要学三级大纲、上下文装配、自定义智能体等概念（文档共 27 篇教程）。**【官方】**
- **纯文学/实验写作**：官方 FAQ 直接说"纯文学、实验性写作 AI 还差得远"。**【官方】**[FAQ 50 问](https://maliangwriter.com/blog/ai-novel-writing-faq-50/)
- **需要移动端/离线写作的人**：无原生 App，仅 Web（手机浏览器"基本操作没问题"）。**【官方】**

### 2.2 一键开书的产出结构（重点拆解）

一次运行固定产出 **5 类结构化产物**，且**全部落库**（不是一段聊天文本）**【官方】**：

| 步骤 | 产物 | 规格 | 落到哪里 |
|---|---|---|---|
| 1 | 书名 + 简介 | 简介约 100–200 字，交代核心悬念 | 书籍基本信息 |
| 2 | 核心设定 | **6–10 条**（世界观、力量体系、主要角色、能力边界、背景悬案） | 设定库条目（后续生成自动调用） |
| 3 | 第一卷卷纲 | **10–20 章**的卷级大纲 | 三级大纲·卷纲层 |
| 4 | 前三章蓝图 | 每章情节点规划 | 章节蓝图层 |
| 5 | 前三章正文 | 体验版 ~1000 字/章；标准版 ~2500 字/章（合计 ~7500 字） | 章节正文 |

运行体验细节（对产品设计很有参考价值）：
- 顶部 5 步进度条 + 每步落一张产物卡（书名卡/设定卡/卷纲卡/蓝图卡/章节卡）；
- Agent 协作过程**默认折叠**，可点开"查看完整过程"看 Structure→Setting→Blueprint→Generation 接力；
- **"一杯咖啡的时间"是营销话术，实际常态十来分钟**（官方自己承认不做秒级承诺）；
- 完成后显示"书壳总览 + 本单花费积分 + 耗时"，主按钮「进入编辑器精修」。

### 2.3 文风分身的工作机制（重点拆解）

| 环节 | 细节 | 来源 |
|---|---|---|

### 2.5 界面与交互形态

- **形态：纯 Web（Flutter Web 编译产物）**，无 Windows/Mac 客户端、无 iOS/Android 原生 App、无小程序。手机浏览器可用但官方自己建议在电脑端写。**【官方】FAQ Q15** +【三方】cagcag 收录形态为"网页"。
- **三栏布局**：左＝资料栏（角色/世界观/悬念/章节树/文档区/片段管理）｜中＝富文本编辑器（Flutter Quill，支持上千章连续滚动）｜右＝AI 助手（会话 + 模式切换 + 审批）。
- **内容层级：作品 → 卷 → 章节 → 场景**（四级），比多数竞品多一层"场景"。
- **双视图**：沉浸式写作视图 ↔ 文档管理视图（一键切换，去掉干扰）。
- **AI 产出必须过"审批"才能入正文**，改写走"差异对比/逐段接受-拒绝-合并"，不直接覆盖原文——这个交互约束值得抄。
- **编排可视化**：Agent 执行过程可展开查看（任务执行图/长文写作任务面板）。

## 3. 工作流拆解（从灵感到成稿的实际操作路径）

### 路径 A：零起点开新书（官方主推，≈10–20 分钟到"可写状态"）

1. **入口二选一**：首页灵感输入框 → 选「极速开书」；或在小说列表新建时打开"极速模式"开关。**【官方】**
2. **输入一句话灵感**（例："一个能听见植物说话的都市女孩，发现小区花坛里的老槐树知道三十年前一桩悬案的真相"）。
3. **看预算再启动**：系统给出**预估积分上限**并校验余额（余额不足→一次模型调用都不发生，避免"跑一半烧光钱"）。
4. **选版本**：体验版（1000 字/章，固定经济模型，每号限 1 次）或标准版（2500 字/章，可选模型档）。
5. **5 步流水线自动跑**：书名简介 → 核心设定 → 第一卷卷纲 → 前三章蓝图 → 前三章正文；每步落一张产物卡，过程可折叠/展开。
6. **中断保护**：跑到第 4 步断了 → 显示"已完成 3/5 步（产物已保存）"→ 充值后点「从第 4 步继续」，前三步不重跑、不重复扣费。
7. **进编辑器精修**：重点改开篇前 500 字钩子、每章结尾悬念、主角对白（官方明确"AI 写对话容易所有角色一个腔调，必须人工纠正"）。
8. **补资产**：把第一章已坐实的信息回填角色卡/设定卡/伏笔，形成"第一章即资料库起点"的闭环。
9. **绑定文风分身**（可选，但建议在生成前做）：喂 2–5 段代表作 → 提炼特征卡 → 试写对比 → 绑定本书。
10. **投稿前体检**：AI 率检测（风险热力图）→ 只改高危段 → 去 AI 味改写（逐段接受）→ 错别字/重复/排版 → 最后生成封面。

### 路径 B：已有存稿续写（迁移场景）

1. 首页「导入小说」→ 上传 **TXT** → 系统智能解析目录结构 → **后台大模型批量生成每章大纲**（这一步很关键，把"别人的旧稿"变成"有结构的项目"）。**【官方】+【三方】GitHub**
2. 整理设定：左栏录入角色/地点/力量体系/悬念 → 知识图谱从正文自动抽取实体补全。
3. 跑**整本一致性体检**，定位吃书/伏笔断线/时间线漏洞。
4. 选模型与协作模式（日常单 Agent、卷首/高潮多 Agent）→ 逐章续写 → 审批入正文。
5. 节奏分析找拖后腿章节 → 章节基准对比（雷达图）→ 交给 Agent 定向修订。

### 路径 C：卡文救急（单点提效）

- **剧情推演**：多模型抽卡出 3–N 个后续走向 → 不满意的单个重生成 → 一键应用到章纲。
- **爆款仿写**：公共库挑对标书 → 拆解报告看节奏曲线/角色关系 → "添加到我的小说"迁移套路 → 二次本地化。
- **免费工具直接救**：黄金三章体检、爽点节奏分析、去 AI 味（不登录也能用一部分）。

### 路径 D：日更批量生产（付费档）

- 前期规划用多 Agent，中期批量生成用单 Agent + 便宜模型（DeepSeek V3/Gemini Flash），关键章再上 Claude Sonnet。
- 用"上下文装配"关掉不需要的设定全文，只给名称 → 省 token。
- 官方称该工作流现实产出 **1–3 万字/天**（生成速度理论 6–10 万字/天）。

## 5. 优点（具体、可验证）

1. **"产物落库"而非"产出文本"——这是它最硬的结构性优势。** 极速开书/推演/拆书的每一样产出都进设定库、三级大纲、角色卡、故事线，下一次生成会自动检索；官方对此的表述很准确："聊天 AI 给你的是一次性烟花，极速开书给你的是一套能持续运转的创作系统的初始状态"。
2. **断点续跑 + 预算上限预估 + 余额前置校验**，三项组合在同类工具里很少见，直接消灭"跑一半没钱/断网全废"这个最伤信任的场景。
3. **文风分身的工程取舍成熟**：选 few-shot 注入而非微调——即建即用、随改随生效、提炼失败或跳过仍可用；再加"可手工编辑的特征卡 + 试写对比 + 书级绑定 + 圈选存样本"四件套，比单纯"上传样章"完整得多。
4. **多模型自由度真的高**：15+ 模型、**按 Agent 分别指定**、自定义 API Key、Ollama 本地模型、预设模板——不被单一底模绑死，也让"贵的模型只用在刀刃上"成为可执行策略。
5. **一致性工程成体系**：知识图谱 + 按卷渐进披露（对 AI 隐藏设定防剧透）+ 整本一致性体检 + 伏笔台账（FORESHADOWING 线标记埋设/回收位），这三层是"百万字不烂尾"的真实工程答案。
6. **诊断能力数据化**：节奏分析出多维评分和情绪曲线、章节可与爆款基准雷达对比、低分章节可直接派给 Agent 修——把"我觉得不好看"变成"第 37 章断章张力弱"，改稿有靶子。
7. **投稿前闭环完整**：AI 率检测（风险热力图 + 只改高危段）→ 去 AI 味 → 错别字/重复/排版 → 过程存证。虽然官方诚实声明"不等于投稿平台结论"，但这条链路是中文网文场景独有的。
8. **上下文装配面板**：显式告诉用户"这次生成看了多少资料、烧了多少 token"，可逐项开关——把成本控制权交还作者，同类产品普遍缺失。
9. **免登录免费工具矩阵（20+）做获客**：去 AI 味、AI 味浓度、黄金三章体检、爽点节奏、命名/简介生成器……每一个都精准卡住网文作者的搜索词，形成极低成本的 SEO 漏斗（配合 `llms.txt` 做 AI 搜索优化，这一手很新）。
10. **开源可自建（Apache 2.0）**：Flutter Web + Spring Boot + Docker 一键部署，对小团队/工作室/想私有化的机构是真实选项，也侧面背书了工程完整度。
11. **中文网文垂类细节到位**：番茄/起点/盐选三套简介模板、卷纲按"3–5 万字阶段爆点"、爽点节奏分析、公共库按番茄榜单组织——不是把英文写作工具翻译一遍。

## 6. 缺点（具体、有据）

1. **稳定性与售后是最大信任风险（有实证投诉）。** 2026-10-09 黑猫投诉（编号 17402140655）：用户购买 ¥99「字数包-大积分包」后"页面频繁闪跳崩溃，长篇小说内容全部丢失且无法找回"，要求退款，商家 72 小时未回应，平台"商家未匹配成功"。**【三方】[投诉](https://tousu.sina.com.cn/complaint/view/17402140655?sld=16ce8bf71cc549d2ecaec20923e25640)**
2. **"一经支付不予退款"是条款明文**，且赔偿上限锁定为过去 12 个月实付金额——与稳定性问题叠加，用户维权空间极小。**【官方】条款**
3. **主体极轻**：注册资本 3 万元、2025 年 5 月成立、客服主渠道是 QQ 群（"需付费用户验证后获取"）、无电话客服。对"把几十万字身家放在这里"的作者，这是结构性不安。**【官方】关于页/页脚**
4. **积分换算不透明**：官方两套口径相差 ~48 倍（200 字/积分 vs 4 字/积分），且明说"不把积分换算成承诺字数"。用户无法预判长篇总成本，只能事后看账单。**【官方】+【接口】**
5. **学习成本高、概念密度大**：三级大纲、知识图谱、上下文装配、渐进披露、自定义智能体、单/多智能体/技能三种模式、审批流……文档 27 篇。官方自己承认新手"最容易迷路的三个地方"。对"只想今天写完一章"的人是负担。**【官方】文档中心**
6. **配置漂移严重、口径自相矛盾**：免费版"仅基础模型"vs 功能页"15+ 模型"；FAQ 说"支持 6 个主流模型"vs llms.txt "15+"；免费档"每天 300 积分"vs 接口字段为 0；关于页"LangGraph"vs 代码"LangChain4j"。**同一官网多处打架，说明内容由营销自动化生成、缺少统一治理。**【官方/接口/三方】对比
7. **SEO 内容农场化，自评横评伤害可信度**：站内 `/compare/` 有近 30 个对比页，"8 款工具横评"里给自己打 **89 分**、笔灵 65、蛙蛙 68、Kimi 45，评分依据却是"站内数据"。这类页面明显是模板批量生成（同一套 Folio/№ 编号、同样的"Fair Play"段落）——短期吃流量，长期被作者识破后反噬品牌。**【官方】**[横评页](https://maliangwriter.com/compare/best-ai-for-chinese-web-novel-2026/)
8. **纯 Web + Flutter Web 的输入/性能天花板**：Web 富文本承载千章滚动，中文输入法、长文档性能、移动端体验都受限；无原生 App/桌面端、无离线写作。官方也承认手机端"基本操作没问题"（=体验一般）。**【官方】FAQ Q15**
9. **数据可迁移性差**：导出只有 TXT/Word（未见 EPUB/Markdown）；知识图谱、故事线、文风特征卡、设定树**无法导出**——一旦不满意或平台停服，最有价值的"结构化资产"带不走。**【待核实，官网未见资产导出说明】**
10. **"番茄直连拆书"踩合规灰区**：依赖第三方爬取服务抓取番茄全文，官方 README 自己写明"需配置第三方服务地址与访问权限"。版权与合规风险由使用者承担，且这类服务随时可能失效。**【三方】GitHub**
11. **强依赖第三方检测引擎做"合规"**：AI 检测走 Pangram（pangram-4），去 AI 味也是启发式改写，官方自己声明"是修改参考，不等于投稿平台结论"。番茄 2026 年已严打 AI 水文（站内博客自述 49 位金番作者被罚、15 万本书被处置），**工具无法给合规兜底**。**【官方】**[番茄严打解读](https://maliangwriter.com/blog/fanqie-ai-crackdown-2026-guide/)
12. **不支持多人协作**（开源版标"未来"），工作室/编剧团队场景缺失。
13. **"AI 引擎 V4.0""7 Agent"更像叙事包装**：多智能体在实现上主要是"同一模型的多角色 Prompt 编排"，官方也承认文风分身是 few-shot 而非微调——"7 个专业 AI"的独立性与真实收益缺少可验证数据（仅自测"矛盾率降低 72%"）。**【官方】自测口径**

| 10 | **AI 产出必须过"审批"才入正文** | 降低"AI 污染原稿"的恐惧，是心理安全感设计 | 生成结果进暂存区，diff 视图，逐段接受 |

### 7.2 可以做差异化的点（它的短板就是我们的机会）

| 它的短板 | 我们的差异化打法 |
|---|---|
| **稳定性/丢稿、条款不退款、主体极轻** | **本地优先（Local-first）+ 每次生成自动版本快照 + 一键导出全量资产包（Markdown/JSON/EPUB）**；把"你的稿子永远是你的、随时能带走"做成第一卖点。这在它那儿是明牌弱点。 |
| **积分黑箱、48 倍换算差** | **按字报价**（"每千字 X 元，含改写/检测"）或**字数包直售**，把不确定性从用户身上挪走；页面上直接给"30 万字长篇预估总成本"。 |
| **学习成本高、概念多** | **默认模板即战力**：开箱选"番茄男频玄幻"模板 → 直接能写，进阶概念（图谱/装配/自定义 Agent）折叠到二级；用"今天只想写完一章"作为主路径而非支线。 |
| **纯 Web、无移动/离线** | **移动端做"轻场景"**（审稿、改一段、看节奏报告、语音记灵感）而非全功能移植；桌面端做本地文件直读 + 离线写作。 |
| **导出与资产锁定** | 把"知识图谱/角色关系/大纲可导出为通用格式（JSON/CSV/Mermaid）"做成开放能力，甚至支持导入到别的工具——反向建立"数据主权"口碑。 |
| **多人协作缺失** | 工作室/编剧团队场景：多人共编一本书、角色卡分工维护、成本按人分摊。它的架构里明确写着"未来"。 |
| **自评横评式 SEO（89 分）伤信任** | **不做自评打分**。改做"可复现的公开基准"：同一 prompt、同一模型、同一章节任务，公开原文与耗时/成本，让作者自己判断。 |
| **"7 Agent" 叙事强于实证** | 少讲角色数，多给**可验证指标**：同一章在"开/关某能力"下的耗时、token、人工返工率对比。 |
| **AI 检测只能"参考"** | 与投稿平台规则对齐的**风险分级 + 可解释依据**（哪一段、因何被判风险、怎么改），而不是只给一个百分比。 |

### 7.3 需要警惕/不要照抄

- ❌ **不要做"多档积分 × 多模型 × 多任务"的三维计费**——它的复杂度已经把用户绕晕，我们应做减法。
- ❌ **不要碰"第三方抓取热门平台全文"的拆书**（番茄直连）。合规风险高、随时失效，且会污染品牌。
- ❌ **不要用"一句话出爆款/日更 1 万字"式夸大文案**——官方 FAQ 与博客里其实很克制（"AI 是工具不是代笔""一杯咖啡的时间不是承诺"），但首页和对比页又在夸大；这种前后不一最伤复购。
- ⚠️ 注意它已经用 **700+ 本公共拆书库 + 20+ 免费工具 + 30 个对比页 + llms.txt** 把中文网文 SEO 词位基本吃满，正面抢词成本高 → 我们应走"细分题材/细分平台（盐选短篇、短剧改编、同人）"的长尾。

## 8. 一句话结论（给决策用）

> 马良写作是**中文 AI 小说工具里"结构化 + 一致性 + 诊断"做得最深的一家**，产品思路（产物落库、断点续跑、可编辑文风卡、上下文装配、渐进披露）值得系统学习；但它的**商业信任（3 万注册资本、不退款条款、真实丢稿投诉）、计费透明度、Web-only 与技术口径混乱**是明确软肋。**抄它的产品结构，反它的信任短板。**
