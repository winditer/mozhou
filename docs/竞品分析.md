## 一、三句话看懂三家

| 维度 | 蛙蛙写作 | 马良写作 | FeelFish |

**30 秒读懂三家的差异**：三家都不承认自己"只是 AI 续写工具"，但拒绝对象各不相同——蛙蛙拒绝"停在小说"，它把价值链往后延伸到短剧与漫剧，卖的是**改编链路**；马良拒绝"停在文本"，它把价值链往里收，卖的是**结构化管理**；FeelFish 拒绝"停在网页"，它把价值链往下沉到**本地文件系统与工具生态**。用一句判断概括：蛙蛙在横向上做宽（多体裁），马良在纵向上做深（单本长文的一致性），FeelFish 在形态上做重（桌面原生 + 可编排 Agent）。

这个差异决定了三家的天花板与短路点：蛙蛙复用价值最高——设定一次投入、三个环节都吃得到，留存天然最强，但改编环节的质量不由它控制（视频质量、剧本可行性都要人工验证）；马良机制密度最高，产物落库、断点续跑、渐进披露是同类最完整的工程答案，但复杂度把新手挡在门外，信任基础极薄（注册资本 3 万元、条款不退款、有真实丢稿投诉）；FeelFish 形态最"专业"，敢公开拒绝"数字泔水"、把自主度砍到"关键节点必须人工确认"，这份克制换来口碑，也换来最陡的学习曲线与最窄的试用窗口（免费档约 5000 字/月）。

## 三、逐家深拆

### 3.1 蛙蛙写作

#### 3.1.1 定位与用户

蛙蛙的自我定义不是"AI 写作软件"而是"故事 IP 生产工作台"。差别很实质：写作软件交付的终点是**文本**，工作台交付的终点是**可继续加工的资产**——正文、剧本草稿、漫剧素材共享同一套人物与设定。它的术语（卷、章、细纲、剧集、场次、对白）全取自中文网文与短剧行业，不是从英文工具翻译来的。

| 人群 | 真实需求 | 蛙蛙给的答案 |
|---|---|---|
| 连载网文作者 | 长期维护一本几十万字的书，逐章续写/扩写/润色 | 人物/背景/大纲/卷章同库维护，AI 对话辅助改稿 |
| 短剧、漫剧团队 | 把故事变成能拍的分集剧本 | 剧集/细纲/场次原生结构，非文本硬套格式 |
| 编辑与内容工作室 | 用 AI 出情节分支、场景候选、修改建议，人做终审 | 拆书分析 + 工作流市场 + AI 工具广场 |
| 改编需求方 | 从已有小说提取剧情与人物关系 | "小说转剧本"专用链路，按所选模型与类型生成改编草稿 |

它明确不服务的两类人也值得记录：一是希望"一句话生成即可投稿"的用户（因为它的链路终点需要人工终审），二是上传无授权作品做商业改编的用户（版权风险自担）。

#### 3.1.2 功能矩阵

| 功能 | 说明 | 亮点评级 |
|---|---|---|
| 长短篇小说工作台 | 题材、人物、背景、大纲、章节起步；续写/扩写/润色/AI 对话 | ★★★★ |
| 项目设定与连续写作 | 角色、势力、背景、卷章、目标读者作为项目上下文 | ★★★★ |
| **剧本创作** | 剧本项目、剧集、细纲管理，按短剧/漫剧组织场景与对白 | ★★★★★ |
| **小说转剧本** | 抽取剧情与人物关系，按模型与类型生成改编草稿 | ★★★★★ |
| 漫剧视频 | 小说/剧本继续进视频生产链路，选模型、素材、时长 | ★★★★ |
| 拆书分析 | 作品结构分析 + 提示工具 + 工作流市场，找结构与改稿方向 | ★★★★ |
| 投稿中心 | 站内投稿入口，连接创作与分发 | ★★★ |
| 导入/导出/回收站 | 卷章、草稿、作品管理，支持恢复 | ★★★ |
| 工作流市场 / AI 工具广场 | 复用他人工作流与工具模板 | ★★★ |

两项五星都在剧本侧——这是产品意图的声明：蛙蛙想赢的是"小说到剧本"这一段，不是"从零到一章"。

#### 3.1.3 核心工作流（七步）

1. **立项目**：选题材与类型，建长篇或剧本项目。
2. **填设定**：人物、势力、背景、时间线、目标读者，作为后续全部生成的上下文基准。
3. **搭大纲**：卷 → 章 → 细纲，先出结构再落字。
4. **逐章生成**：续写/扩写/润色，AI 对话辅助改稿，人工审稿并**回写新设定**。
5. **改编分叉**（可选）：小说转剧本，抽取剧情与人物关系，生成短剧/漫剧剧本草稿。
6. **视频化**（可选）：剧本继续进漫剧视频链路，按任务页选模型、素材、时长。
7. **导出交付**：导出阶段版本，同步本地备份。

第 4 步里"回写新设定"这个动作是整个工作流的枢纽。它意味着每次写作都在加厚资产，而不是消费资产——这也是第七步之后用户更难离开的原因：换一个工具，等于把已经长出来的设定树推倒重来。

#### 3.1.4 三个最值得学的设计

**（1）短剧/漫剧的原生结构，而不是"把小说套进剧本模板"。** 大多数工具做剧本的方式是给一段文本套上"场景一、场景二"的壳。蛙蛙把剧集、细纲、场次、对白做成数据结构，于是"第 3 集第 7 场需要一句反转台词"这种需求可以被精确定位、单独生成、单独修改。结构化的收益不在生成质量，而在**可寻址性**——你能指名要改哪一块。通用大模型对话给不了这种可寻址性。

**（2）小说转剧本：把"改编"做成一条有专用工具（如"孤星"系列）的链路。** 改编的真实工作量在信息压缩：三十万字小说要压成二十四集、每集 90 秒钩子的剧本，必须先把"哪些情节必须留、哪些人物可以合、哪条支线可以砍"结构化。蛙蛙"先抽再生成"的顺序是对的；直接让模型"把小说改成剧本"只会得到四不像的摘要。

**（3）设定资产跨阶段复用。** 这是蛙蛙真正的护城河，且它不在单点生成质量上。写到剧本不必重新交代人物性格，写到视频不必重新描述场景，因为设定一直挂在项目上。复用价值即迁移成本的倒数：把三阶段串成一条线，等于一次性收走用户三次"重新开始"的成本。

#### 3.1.5 定价与商业模式

蛙蛙采用**动态权益体系**，未见稳定公开的价目表，因此具体金额在素材中一律标注未查证，本报告不做推算。

| 权益类型 | 作用 | 使用前必须核对 |
|---|---|---|
| 免费体验 | 注册即得有限次数 | 赠送数量、到期时间、可用模型、导出限制 |
| 会员订阅（月/年） | 按期获得蛙币 + 会员权益 | 周期、自动续费、每月发放、到期失效、退款规则 |
| 无限卡 | 限定期内部分小说/剧本基础 AI 功能免蛙币 | 高级模型、拆书、转剧本、漫剧视频通常**不在**范围内 |
| 蛙币 | 平台通用消耗单位，写作与视频任务共用 | 单任务预估、失败是否扣费、有效期 |
| 蛙币补充包 | 补充额度 | 同上 |
| 专项任务 | 拆书、小说转剧本、视频等独立计费流程 | 模型、字数、集数、时长、重试与交付条件 |

- 会员具体月费/年费金额：**未查证**（官方页面标注价格可调整；旧文章中的固定月费与"无限字数"表述不可引用）。
- 支付由第三方处理，条款写明价格可调整且通常不退款。
- 唯一可靠的成本测算方法：**用一章真实内容跑一遍，记录"实际可采用输出"消耗的蛙币**，不要用生成总字数去估算整本书——因为"无限卡"覆盖范围、模型档位、重试次数三者相乘，误差可以到数倍。

#### 3.1.6 三个最致命的短板

**（1）四层权益叠加，导致价格不可预期。** 会员 + 蛙币 + 无限卡 + 专项任务是四种不同性质的计费物，用户要回答"我这本 30 万字大概花多少钱"，必须同时知道：会员每月发多少蛙币、无限卡覆盖哪些功能、哪些任务跳出无限卡、失败是否退币、模型档位系数多少。任何一个未知，答案就是不可算。素材里给的操作建议（用一章实测）本质上是承认"事前无法估算"——这在订阅制产品里是结构性缺陷，不是文案问题。

**（2）"无限"有边界，预期落差是自找的。** 拆书、转剧本、漫剧视频与高级模型基本都在无限卡之外。用户在"无限卡"这三个字上建立的预期，会在第一次跑转剧本时崩掉。这类落差不产生投诉，产生的是沉默流失——用户不会争论，只会不再续费。

**（3）权利与数据说明不清，且无公开 API/SDK。** 版权归属、训练用途、第三方处理、服务器留存与永久删除策略缺乏明确公开说明；同时没有公开 API/SDK，意味着无法做生产级集成、批量自动化，工作室与二次开发场景被卡死。第三点尤其影响 B 端：一个内容工作室要做流水线，第一件事就是问"能不能程序化调用"，蛙蛙的答案是"不能"。

#### 3.2.3 核心工作流

**路径 A：零起点开新书（官方主推，约 10–20 分钟到"可写状态"）**

1. 首页灵感输入框选「极速开书」，或在新建时打开"极速模式"。
2. 输入一句话灵感（例："一个能听见植物说话的都市女孩，发现小区花坛里的老槐树知道三十年前一桩悬案的真相"）。
3. **看预算再启动**：系统给预估积分上限并校验余额——余额不足时**一次模型调用都不发生**。
4. 选版本：体验版（1000 字/章，固定经济模型，每号限 1 次）或标准版（2500 字/章，可选模型档）。
5. 5 步流水线自动跑，每步落一张产物卡；Agent 协作过程默认折叠，可展开看 Structure→Setting→Blueprint→Generation 接力。
6. **中断保护**：跑到第 4 步断了 → 显示"已完成 3/5 步（产物已保存）"→ 充值后点「从第 4 步继续」，前三步不重跑、不重复扣费。
7. 进编辑器精修：重点改开篇前 500 字钩子、每章结尾悬念、主角对白（官方明确"AI 写对话容易所有角色一个腔调"）。
8. 补资产：把第一章已坐实的信息回填角色卡/设定卡/伏笔——"第一章即资料库起点"。
9. 绑定文风分身（建议在生成前做）。
10. 投稿前体检：AI 率检测 → 只改高危段 → 去 AI 味逐段接受 → 错别字/重复/排版 → 生成封面。

**路径 B：已有存稿续写**——导入 TXT → 后台批量生成每章大纲（把"别人的旧稿"变成"有结构的项目"）→ 录设定 → 跑整本一致性体检 → 逐章续写并审批 → 节奏分析定位拖后腿章节 → 派给 Agent 定向修订。**路径 C：卡文救急**——剧情推演多模型抽卡、单项重生成、一键应用到章纲；或挑对标书看拆解报告迁移套路；或直接用免登录工具体检。**路径 D：日更批量生产（付费档）**——前期多 Agent 规划，中期单 Agent + 便宜模型，关键章上 Claude Sonnet，用上下文装配只给设定名称省 token；官方称该工作流现实产出 **1–3 万字/天**（生成速度理论 6–10 万字/天）。

#### 3.2.4 三个最值得学的设计

**（1）一键开书的"产物卡落库"：把"生成一段文本"升级为"初始化一个项目"。**

一次运行固定产出 5 类结构化产物，且**全部落库**，不是一段聊天记录：

| 步骤 | 产物 | 规格 | 落到哪里 |
|---|---|---|---|
| 1 | 书名 + 简介 | 简介约 100–200 字，交代核心悬念 | 书籍基本信息 |
| 2 | 核心设定 | **6–10 条**（世界观、力量体系、主要角色、能力边界、背景悬案） | 设定库条目（后续生成自动调用） |
| 3 | 第一卷卷纲 | **10–20 章**的卷级大纲 | 三级大纲·卷纲层 |
| 4 | 前三章蓝图 | 每章情节点规划 | 章节蓝图层 |
| 5 | 前三章正文 | 体验版 ~1000 字/章；标准版 ~2500 字/章（合计 ~7500 字） | 章节正文 |

三个体验细节值得记：5 步进度条 + 每步一张**可编辑的产物卡**；完成后显示"书壳总览 + 本单花费积分 + 耗时"，主按钮是「进入编辑器精修」而非「重新生成」；官方自己承认"一杯咖啡的时间"是话术、**实际常态十来分钟**——把预期锚在真实值上，比"3 分钟写完一本书"更能保住复购。

配套的是**三件套防"跑一半废了"机制**：①启动前给积分上限预估（上限是上限，实际通常更低）②余额前置校验（不足则零调用，不烧钱）③断点续跑（已完成步骤产物加锁，续跑按 step 幂等，不重复扣费）。这三件组合在同类工具里很少见，而"跑到第 4 步没钱了/断网了"恰恰是最伤信任的场景。

**（2）文风分身：few-shot 注入而非微调，用"可编辑特征卡"把黑箱变规则。**

| 环节 | 细节 |
|---|---|
| 喂料 | 2–5 段，每段 200–800 字，总量 **≤5000 字硬校验**；建议"一段对话+一段描写+一段心理+一段叙事推进"，覆盖优于堆量 |
| 提炼 | 输出 **3–6 条可执行特征**（如"短句为主，一句话不超过 20 字""对话密度高""偏爱具体名词、少用四字成语"），每条可手改/删除；**允许跳过提炼**只做样本注入 |
| 技术路线 | **few-shot 样本注入（Prompt 拼接）**，非微调、非 LoRA；样本与特征卡占输入 token，实际消耗比不开时略高 |
| 应用 | 全局默认 / 绑定指定小说（**书级优先于全局**）；输入框上方 chip 可临时关掉 |
| 槽位与费用 | 免费 1 / 基础 3 / 专业 5 / 旗舰 8 个；降档后超出的分身**停用不删除**；提炼 5 积分/次；试写对比 1–3 积分/次 |
| 验收 | 保存后进**试写对比**：同引子左右各写 ~150 字（左裸写/右带分身），差异肉眼可见 |
| 组合 | 与免费「去 AI 味改写」叠加：既抹机器腔又向你的文风收敛 |

这套设计的聪明之处在于**工程取舍与产品设计互相成就**：选 few-shot 是因为它即建即用、随改随生效、提炼失败还能降级；而正因为是 few-shot，特征卡才必须是"人能看懂、能改"的规则，而不是一堆模型权重。反过来，如果选了微调，"3–6 条可编辑特征卡"这个最有说服力的界面就不存在了。**技术选型决定了你能给用户什么界面**——这是整个产品里最值得抄的一条方法论。

**（3）三层一致性工程 + 审批门：把"百万字不烂尾"拆成可执行动作。**

- **知识图谱**：自动从正文抽角色/地点/物品/势力/事件及关系，生成前检索校验，故事线含伏笔埋设与回收位置标记。官方称 30 万字以上矛盾率降低约 72%（自测口径）。
- **按卷渐进披露**：设定条目可"对 AI 隐藏"，或到第 N 卷才解锁。官方举例：第一卷只让 AI 知道表面身份，第三卷才放出幕后真相。这是**防剧透**——不只是省钱，更是防"AI 提前把底牌打出来"这种最难察觉的质量事故。
- **整本一致性体检**：人设/设定/伏笔/时间线跨章扫描，把"我觉得哪里不对"变成"第 37 章断章张力弱"。
- **审批门**：AI 产出必须过"审批"才入正文，改写走 diff 逐段接受/拒绝/合并，**不直接覆盖原文**。这是心理安全感设计——用户怕的不是 AI 写得差，是 AI 悄悄改坏了他写好的东西。

#### 3.2.6 三个最致命的短板

**（1）商业信任薄到可以量化。** 注册资本 3 万元、2025 年 5 月成立、客服主渠道是 QQ 群（"需付费用户验证后获取"）、无电话客服；条款明写"一经支付不予退款"且赔偿上限锁死在过去 12 个月实付金额。2026-10-09 黑猫投诉（编号 17402140655）：用户购买 ¥99「字数包-大积分包」后"页面频繁闪跳崩溃，长篇小说内容全部丢失且无法找回"，要求退款，商家 72 小时未回应，平台显示"商家未匹配成功"。这不是差评，是**结构性风险**：作者把几十万字身家放在这里，而运营方的赔付能力上限只有 3 万元，条款还先把退款堵掉了。

**（2）积分换算差 48 倍，事前无法估算总成本。** 同一站既说"500 积分≈10 万字"（≈200 字/积分），又说"高档模型跑 7500 字上限 1800 积分"（≈4 字/积分），**相差约 48 倍**，全看模型档位与上下文装配。用户要回答"我这本 30 万字要花多少钱"，官方给的答案是"不把积分换算成承诺字数"。还有两处口径打架：免费档"每天 300 积分"在公开接口里查不到（`creditsGranted: 0`、`dailyBonusCredits: 0`）；¥69 档给 8,750 积分/月而"每天送 290"另计 → 实际月度可用约 17,450，宣传语与额度结构要用户自己算。

**（3）纯 Web + 配置漂移，体验与可信度双重受损。** Flutter Web 富文本承载千章滚动，中文输入法、长文档性能、移动端体验都受限；无桌面端、无原生 App、无离线写作，官方也承认手机端"基本操作没问题"（＝体验一般）。同时官网多处自相矛盾：免费版"仅基础模型"vs 功能页"15+ 模型"；FAQ"支持 6 个主流模型"vs llms.txt"15+"；关于页"LangGraph"vs 代码"LangChain4j"。**同一官网多处打架，说明内容由营销自动化生成、缺少统一治理**——这对一个要求用户托付百万字的工具是硬伤。

其余必须记录的失分项：

- **数据可迁移性差**【待核实】：导出只有 TXT/Word，未见 EPUB/Markdown；知识图谱、故事线、文风特征卡、设定树**无法导出**——最有价值的结构化资产带不走。
- **番茄直连拆书踩合规灰区**：依赖第三方爬取服务抓全文，README 写明"需配置第三方服务地址与访问权限"，风险由使用者承担，服务随时可能失效；番茄 2026 年已严打 AI 水文（站内博客自述 49 位作者被罚、15 万本书被处置），而它的 AI 检测只走第三方引擎 pangram-4，官方明示"不等于投稿平台结论"。
- **"7 Agent"叙事强于实证**：实现上主要是同一模型的多角色 Prompt 编排，独立性缺乏可验证数据（仅自测"矛盾率降低 72%"）。

**一句话结论**：马良是中文 AI 小说工具里"结构化 + 一致性 + 诊断"做得最深的一家，产品结构值得系统学习；但商业信任、计费透明度、Web-only 与技术口径混乱是明确软肋。**抄结构，反短板。**

### 3.3 FeelFish

#### 3.3.1 定位与用户

FeelFish 的自我定义是"桌面级 AI Novel Writing Agent 工作台"。它最准确的类比是**小说版的 Cursor / Claude Code**：文件系统 + Agent + Skills + 审批门，而不是"网页版 AI 续写"。核心资产不是模型，而是 `.feelfish` 项目目录里的规则/角色/设定/章节/智能上下文/智能体/技能，以及一套"AI 只能通过工具改文件、改完要你审批"的机制。

它有一条罕见的、明确写在官方口径里的价值观边界：**"绝不是靠全自动化的方式去生产'数字泔水'，服务对象始终是专业创作者。"** 这句话直接决定了它的 Agent 自主度上限——多步执行 + 关键节点人工确认，而非无人值守跑完整本。在小红书/知乎这类对"AI 味"高度敏感的创作者社区，这是一个有效的信任资产。

核心用户五类：**长篇/连载网文作者**（日更、防人设崩塌、伏笔不丢，是其明确的核心人群）、**严肃文学/多卷本作者**（要结构、主题、文风稳定）、**编剧/剧本作者**（人物小传、分场大纲、对白；官网 FAQ 明确"可以写剧本"，但非剧本排版工具）、**网文工作室/团队**（统一流程、技能可 Git 共享与发市场）、**已有固定 SOP 的进阶用户**（自定义方案为 3.0 主打）。

**它主动放弃三类人**：手机重度创作者、想"一句话生成整本"的尝鲜用户、只想浏览器即开即用的人。这是战略取舍而非能力缺失——但也正是市场上人数最多的三类，后面会看到这个取舍如何反噬它的转化漏斗。

#### 3.3.3 核心工作流（十步）

```
① 建项目（小说/剧本/自由创作/拆书）→ ② Agent 对话搭框架（风格规则→角色卡→世界观→分卷大纲）
→ ③ 生成「智能上下文」（读已写正文，抽取 风格/角色近况/剧情记录/伏笔清单/关系图）
→ ④ 配「方案」：选内置（专业辅助/多智能体/智能规划/游戏冒险）或自建，指定主智能体、技能、模型
→ ⑤ 写章节：A 智能规划模式（计划→确认→大纲→确认→正文→自动回写文档）或 B 专业辅助模式（对话 / Cmd+K 就地改写）
→ ⑥ 审稿：Diff 待确认变更 → 逐段接受或退回；段落标注 + 引用原文喂给 AI 精准改
→ ⑦ 一致性维护：智能上下文按需增量更新（默认 78% 触发压缩）→ ⑧ 多部门并行（编辑部写正文 ‖ 质检部审前章 ‖ 秘书部管配置导出）
→ ⑨ 沉淀：有效做法写成 SKILL.md，复用或发市场 → ⑩ 交付：云同步 + 项目时光机保底 → 导出 / 朗读 / 转漫剧视频
```

**Agent 自主度的真实边界**，这张表比任何功能介绍都能说明它是什么产品：

| 环节 | 自主度 | 证据 |
|---|---|---|
| 读哪些文件 | **高**：Agent 主动调工具读文件，不必你贴 | 「AI 需要读取文件内容，是可以主动调用工具读取」 |
| 多步任务推进 | **高**：以任务列表推进整章创作 | 「要求 AI 必须以任务列表的方式来推进每一章的创作」 |
| 计划/大纲 | **低**：必须你确认才继续 | 「只有在你确认后，AI 才会开始执行」 |
| 改文件 | **中**：改前给 Diff，改后可回滚 | 4.0 待确认变更 + 单文件历史 |
| 文档回写 | **高**：写完自动更新角色/设定/剧情记录 | 智能规划模式的收尾动作 |
| 跨部门派单 | **中高**：AI 判断归属并转接，但有确认提示 | 「自动帮你转接」+ 确认提示 |
| 一次跑完一本 | **明确不做** | 拒绝"数字泔水"、拒绝全自动 |

这就是「**Human-in-the-loop 的自动化**」：每个"高自主"环节都嵌了一个审批门，用自主度换可控性。

#### 3.3.4 三个最值得学的设计

**（1）智能上下文：用"信息密度"对抗"窗口爆炸"。**

这是全案最有洞察力的机制。长篇写作有个反直觉的真问题：**设定文件越长越难用**。写到 50 万字时角色卡 30 人、设定库 80 条、剧情记录 200 条，全塞给模型会稀释注意力，效果反而比只给摘要更差。

FeelFish 的解法是让 AI 从**已写正文**里反向抽取五类摘要：风格、角色近况、剧情记录、伏笔清单、角色关系图。关键设计有三点：

- **不可手改**。这一条看着反直觉（用户不能编辑自己的资料？），但正是它保证了摘要与正文的一致性——手改就引入了第二个真相来源，而双真相正是吃书的起点。
- **可自定义抽取提示词**，且支持多份按名区分（不同卷、不同视角各一份）。
- **配合自动压缩阈值**（默认 78%，可调 50–70%）形成"临界点自动降维"的闭环。

它解决的不是"给模型更多信息"，而是"给模型更少但更密的信号"。这条判断对整个品类都成立。

**（2）部门隐喻替代技术术语：命名即产品。**

编辑部 / 秘书部 / 质检部本质是"多 Agent 并发 + 任务分派 + 角色分工"，但直接叫"多智能体编排 / ReAct 循环"，作者群体根本不会用。换成部门隐喻后三个收益同时发生：立刻理解谁干什么；派单变成"把稿子交给质检部"这种自然语言；每个部门可独立绑模型，成本控制变成"便宜部门用便宜模型"。配套的**秘书部**把"软件操作本身"也做成 Agent（建项目、配模型、导文稿、找回版本），等于把设置页包装成同事——**作者不理解 Agent，但理解同事**。

**（3）Skill 体系对齐 Claude 生态：三级渐进式披露 + 可直接迁移的格式。**

`.feelfish/agents/<id>.md` 带 YAML frontmatter（`tools: all|readonly`、`skills: []`），技能走 `SKILL.md` + `references/` 的**渐进式披露三级加载**，MCP 可扩展。这套设计明显对齐 Claude Skills / MCP 生态，连"技能名不能以 Claude/Anthropic 开头"这种约束都继承了。

战略含义是：**兼容 = 可反向收割社区资产**；自造格式 = 从零养生态。当整个 AI 工具生态都在往 SKILL.md / AGENTS.md / MCP 收敛时，一个写作软件选择兼容而不是自造，等于把自己的技能市场接到了外部供给上。

配套两条工程细节：**Diff 预览 + 四层版本保底**（待确认变更 → 单文件历史 → 项目时光机 → 云盘 30 天），AI 改稿最怕丢稿；**智能规划模式的回写闭环**（正文写完自动回写角色/设定/剧情记录/后续计划），等于每章顺手更新知识库——自动化用在"替你记账"而非"替你写"。

#### 3.3.6 三个最致命的短板

**（1）免费额度形同虚设，试用漏斗在最关键的环节断裂。** 免费 500 万积分/月 ≈ **约 5000 字**产出（按 1 亿≈10 万字折算）。写完一章就没了。问题不是"给得少"，而是**给的位置错了**：智能上下文的价值在第 20 章之后才显现（设定越多、摘要越有用），而 5000 字连第 3 章都到不了。用户被卡在"还没体验到最贵卖点"的地方，于是所有对价值的判断都只能基于"这玩意儿好像和网页版差不多"。这是最容易攻击的软肋，缺口就在漏斗中段。

**（2）积分消耗不可预测，且是隐性持续扣费。** 官方自己写明：不只是生成才扣，来回对话、Agent 读文件、秘书部推荐、语义搜索、对话取名、智能上下文更新**全都扣积分**。用户难以预估"写一章要花多少钱"，天然产生"被割"的感受。更糟的是**完整价目表要登录才看**（官网只给 DeepSeek V3.2 一个样例，其余"请登录后访问 /account/credits 查看"）。这直接导致了真实负面口碑：黑猫投诉存在一条题为《FeelFish 宣传不符实，功能虚假还耗积分，退钱并公示》的投诉（编号 17396221061），但页面现已 404/需登录，**正文未能核实**——仅标题可证，可信度需打折。

**（3）"只做桌面"的取舍在产品上正确，在转化上致命。** Windows 10+/macOS/鸿蒙 PC 全功能，手机端只做"看稿/记灵感/远控"且仅高级/专业会员可用；也没有完整网页版。这意味着：新用户想试，必须先下载 115MB 安装包；想在路上改一段，没有路径；iOS App 版本 1.1.1、评分 **1.0/5（仅 1 条评分）**、语言标注"英语"。第三方文章也把"只有 PC 客户端、没有 APP 和完整网页版"列为用户最常抱怨的点。**它用形态换来了生产力，也换来了最低的试用转化率。**

其余必须记录的失分项：

- **多设备并发编辑会冲突**：只能手工选"本地覆盖云/云覆盖本地"。
- **上下文窗口仍是硬约束，认知负担转嫁给用户**：官方文档整篇在教"别一次带太多文件""每个章节新开对话"——不是开箱即用，是要学。
- **无设定冲突检测**：明明有智能上下文 + 关系图 + 伏笔清单这些原料，却没做矛盾扫描/标红。这是能力版图上最明显的洞（且被大量软文误传为已有功能）。
- **无团队协作、无 API/CLI**：单用户本地目录 + 云盘备份，工作室只能"共用账号/传项目包"。
- **导出能力表述含糊**：官方只提"导出文稿"，格式清单**未查证**——对要投平台的作者，导出与排版是硬决策项。
- **迭代激进导致版本割裂**：4.0 → 4.0.48 → 4.1.0 **beta 需手动安装**，且 4.1 加了视频/漫剧/有声书等存疑能力。

## 四、三家共同的产品范式

把三家的功能表叠在一起看，会发现它们在不同位置做了同一件事。下面七条规律不是"行业趋势"，而是**从这三家的具体实现里能反推出的设计定律**——每一条都能找到至少两家的独立证据。

| # | 规律 | 支撑证据 |
|---|---|---|
| 1 | **卖的不是"会写字"，是结构化资产落库。** 模型是公共品，产品价值在于把这次生成变成下次生成可调用的数据。 | 马良极速开书 5 类产物**全部落库**（设定库/卷纲层/蓝图层/正文），官方原话"聊天 AI 给你的是一次性烟花"；FeelFish 把规则/角色/设定/智能上下文固化成 `.feelfish` 目录；蛙蛙设定跨小说/剧本/视频复用。三家都在做"生成→沉淀→再生成"闭环。 |
| 2 | **一致性靠"上下文工程"，不靠更大的模型。** 没有一家把"用了最强模型"当卖点，全在做检索、摘要、投放时机。 | 马良：知识图谱 + 按卷渐进披露 + 上下文装配面板；FeelFish：五层文件分离 + 智能上下文 + 逐项勾选 + 78% 自动压缩；蛙蛙：项目设定 + 细纲注入。三家底模高度重合（DeepSeek/Claude/Gemini），差异全在上下文层。 |
| 3 | **长文生成必须可断点、可审批、可回滚。** 不是体验优化，是"敢不敢把长篇交给它"的准入门槛。 | 断点：马良「已完成 3/5 步（产物已保存）」+ 续跑按 step 幂等不重复扣费；审批：马良产物必过审批入正文、FeelFish 待确认变更 Diff 预览；回滚：FeelFish 单文件历史 + 项目时光机 + 云盘 30 天四层保底。 |
| 4 | **计费透明度是口碑生死线，且三家都在流血。** 越按 token 记账，越答不出"写一章多少钱"；用户无法预算，就默认被割。 | 蛙蛙四层权益叠加、金额多未查证；马良同一站两套换算口径差 **48 倍**且明说"不换算成承诺字数"；FeelFish 完整价目表要登录才看，对话/读文件/语义搜索全扣积分。三家差评关键词高度重叠。 |
| 5 | **数据可迁移性 = 信任；不可迁移 = 锁定，也是差评源。** 结构化资产既是护城河，也是人质。 | 马良导出仅 TXT/Word，图谱/故事线/文风卡/设定树不可导出（待核实）；FeelFish 格式未查证；蛙蛙清单未公开。三家都缺"全量资产包"，而都要求用户托付几十万字。 |
| 6 | **纯 Web 是全品类的形态短板，桌面优先可单独立足。** 写长篇是每天四小时的重度输入场景，浏览器扛不住中文输入法与千章滚动。 | 蛙蛙/马良均纯 Web（马良 Flutter Web 承载千章，官方承认手机端"基本操作没问题"＝一般）；FeelFish 靠三端原生客户端 + 离线可编辑，把形态做成差异点。反证：FeelFish 用户抱怨第一条是"只有 PC 端没 App"——形态是双向取舍。 |
| 7 | **术语是产品的一部分：面向作者的 AI 必须"去技术化"。** 同一套多 Agent 编排，叫法决定可用性。 | FeelFish 用编辑部/秘书部/质检部替代 ReAct/子智能体，把设置页包装成"同事"；马良用"文风分身""审批"这类可感知词，但失败点恰在把"上下文装配""技能模式"直接暴露给作者，官方承认新手"最容易迷路的三个地方"。 |

再补一条反面规律：**"多 Agent 数量"是最不可信的营销指标**。马良的 7 Agent 主要是同一模型的多角色 Prompt 编排，FeelFish 的多部门本质是"多份系统提示 + 任务分派 + 冲突告警"。真差异不在 Agent 个数，而在**产物是否落库、审批门是否强制、上下文是否可观测**。

## 五、市场空白与我们的机会

三家把中文 AI 写作这个品类做到了"能用"，但都有各自结构性放弃的地带。下面九个空白点，每条都标注"他们为什么没做/做不好"——**这个原因比空白本身更重要**，因为它决定了这个空白是"没人想到"还是"想到了但做不了"，前者是机会，后者是陷阱。

| # | 空白点 | 他们为什么没做/做不好 | 我们能怎么做 |
|---|---|---|---|
| 1 | **桌面双平台原生 + 离线可用** | FeelFish 做了，但只覆盖 Win/mac/鸿蒙 PC 且手机端半成品；蛙蛙/马良纯 Web，转桌面等于重写前端。更根本的原因：**云端才好做积分计费与内容风控** | Tauri/Electron 双平台 + **本地优先架构**：正文与资产落本地文件（Markdown + frontmatter 工程目录），只有 AI 调用需联网；离线可读可写可导出。形态本身当卖点："你的稿子在你自己硬盘上。" |
| 2 | **BYOK 与自定义渠道做到极致** | FeelFish 已 BYOK 免费，但只到"能配"：三段协议、无连接诊断、无任务级路由、无费用面板；马良支持 Key/Ollama/OpenRouter 但无按任务路由；蛙蛙没有（它靠蛙币） | 多协议（OpenAI/Claude/Gemini/OpenAI-compatible）+ **多 Key 池与失败自动切换** + **任务级模型路由**（大纲/正文/摘要/校验各绑一个 + 一键预设）+ **连接诊断**（延迟/可用模型列表/首 token 时间）+ **请求级用量与费用明细**（每次调用多少 token、多少钱、哪个 Key）。这是 FeelFish 留下的最大工程缺口。 |
| 3 | **场景广度：不止小说** | 三家都把重心压在长篇小说上——付费意愿最高、资产沉淀最深；短篇/剧本/公众号/短视频脚本都只是"顺带功能"。**组织能力被"长篇"这一种结构绑死了** | 用"题材模板 + 结构模板"解耦：同一套 Agent 与上下文引擎，前端按场景换骨架——短篇（起承转合）、剧本（场次/对白）、公众号（标题+金句+结尾）、小红书（钩子+清单+标签）、短视频（3 秒钩+分镜）、职场（汇报/复盘）、学术（摘要/综述）、品牌（卖点矩阵）。**关键不是多写 prompt，而是让资产跨场景复用。** |
| 4 | **篇幅精确控制（目标字数守护）** | 三家都只能"生成一章"，没人做"这本书 30 万字、当前 8.2 万、按卷配额还剩多少"的预算。原因：长度控制要**跨章状态机**，而它们的生成单元都是"单章一次性调用"，没有全局账本 | 项目级字数预算：设定总目标 → 按卷拆配额 → 每章给"目标字数 ±10%"硬约束；生成时注入长度守护指令（不足自动续写、超出自动收束）；写完更新账本并预警"第 7 卷配额已用 92%"。马良卷纲有"3–5 万字阶段目标"字段，但没做成强制约束。 |
| 5 | **主题系统（视觉 + 排版 + 题材）** | 只有 FeelFish 做了 4 套纸张主题 + 自定义背景 + 霞鹜文楷，其余两家是白底编辑器。原因：主题不影响留存/付费，是典型的"低优先级高感知"，资源永远排不上 | 三层主题：**视觉**（明暗/纸质/护眼/自定义背景/字体）+ **排版**（字号行距/段首缩进/中英混排/稿纸模式）+ **题材主题**（一个"悬疑"主题同时改字体气质、默认语气、常用词汇面板、章节命名习惯）。把主题从"皮肤"升级成"创作气场"，这是唯一能一次改完就立刻被感知的差异化。 |
| 6 | **数据主权：全部本地、可完整导出/备份/迁移** | 马良的图谱/故事线/文风卡不可导出（待核实），FeelFish 格式含糊，蛙蛙清单未公开。**原因是商业动机**：结构化资产是护城河，导出即拆墙；且架构本就长在云端数据库上 | 全量资产包导出：正文 Markdown + 设定/角色/大纲 JSON + 关系图 Mermaid + 智能上下文 Markdown，一个 zip 带走；支持**导入回来**；提供一键本地备份与版本快照。反向宣传："我们敢让你走，因为我们赌你会回来。" 这一条直接吃马良丢稿投诉与"平台停服"焦虑。 |
| 7 | **计费透明：按 token 实报，不卖积分** | 积分是缓冲垫：模型成本波动、缓存命中率都藏在里面，厂商可对冲；改实报等于把毛利暴露给用户。所以三家都选了积分，也都把换算讲得含糊 | **按 token 实报**：每笔请求显示模型、输入/输出 token、单价、小计；页面给"写一章 ≈ ¥X"的实时估算器；设月度预算上限与超额提醒；**失败或中断不扣费**。差异化话术直接对着痛点："我们不卖积分，你看到的就是模型账单 + 一个固定的软件费。" |
| 8 | **无登录可用** | 全部要求注册登录（马良 20+ 免费工具里有一部分可免登录，但那是获客手段）。原因：登录是计费与风控的前置条件 | **无登录即可用**：本地项目、本地模型/BYOK 场景下完全不需要账号；首次启动给一个可直接写的空白项目；云同步/订阅才需要登录。这条对"我只想试 5 分钟"的用户是决定性的——它把 FeelFish 那个"下载 115MB → 注册 → 5000 字用完"的漏斗，换成"打开就能写，写到第 20 章再决定要不要付费"。 |
| 9 | **移动端只做"审稿与审批"** | FeelFish 手机端做了看稿/记灵感/远控，**唯独漏了审 Diff**——只能下指令不能审改动；蛙蛙有 iOS App 但能力未查证；马良没有 App。原因：移动端审批要 Diff 渲染 + 局部接受/拒绝，投入产出比最低 | 手机端只做三件事且做到极致：看稿（含朗读）、记灵感（语音转文字落进素材库）、**审 Diff**（逐段接受/拒绝/合并）。第三件是明确空位，也是"AI 替我写了一章，我在通勤路上把它审掉"这个高频场景的唯一入口。 |

**优先级判断**：真正"对手结构上补不快"的是 1（桌面+本地优先）、6（数据主权）、7（计费透明）——分别要求架构重写、商业让利、承认毛利；3/5/9 属于"他们能补但不想补"，我们必须抢先建立认知；2 与 4 是纯工程活，但 FeelFish 的 BYOK 已跑在前面，我们的差异只能落在"路由 + 诊断 + 费用可见"。

## 六、我们的差异化定位

**一句话定位：一台装在自己电脑里的长篇写作工作台——你的稿子和设定永远在本地、可完整带走；模型用谁的、花多少钱，全部由你决定并逐笔可见。**

三条支撑，逐条对着竞品的硬弱点：

| 支撑 | 承诺的具体形态 | 打的正是谁的软肋 |
|---|---|---|
| **① 本地优先 + 数据主权** | 正文与资产落在本地工程目录（Markdown + frontmatter），无登录可用；一键导出全量资产包（Markdown/JSON/Mermaid/EPUB）并可导回；每章自动快照 | 马良的丢稿投诉（黑猫 17402140655）+ 图谱/文风卡不可导出（待核实）+ 条款"一经支付不予退款"；FeelFish 导出格式至今未查证 |
| **② BYOK 到极致，且不牺牲能力** | 多协议 + 多 Key 池 + 任务级模型路由 + 连接诊断 + 请求级费用明细；配自己的模型即可用全部一致性/上下文能力 | FeelFish 的 BYOK 只到"能配"，缺诊断/路由/费用可见；马良支持 Key 但无任务级路由界面；蛙蛙无 BYOK |
| **③ 计费按 token 实报** | 请求级账单 + 写一章的实时成本估算器 + 月度预算上限 + 失败不扣费；软件费与算力费分开标价 | 马良 48 倍换算差；FeelFish 要登录才看价目且对话/读文件全扣积分；蛙蛙四层权益导致价格不可预期 |

取舍也要说清：**不拼"一键生成整本"**（与审批门的产品哲学冲突），**不拼底模质量**（公共品无壁垒），**不拼价格**（FeelFish 已把每万字打到 ¥0.85–1.7，正面拼是消耗战）。我们拼"可控性 + 可预期 + 可带走"——这三件在中文市场无人认真做过。

## 七、功能取舍建议

| 优先级 | 功能 | 为什么这个优先级 | 验收标准 |
|---|---|---|---|
| **P0** | 本地工程目录 + 无登录可用 + 全量导出/导入 | 定位地基，晚做则架构返工 | 断网可新建/编辑/导出；导出包能在另一台机器完整导回 |
| **P0** | 模型接入层：多协议 + 多 Key + 任务级路由 + 连接诊断 | 与 FeelFish 正面交锋处，它缺诊断与路由 | 三协议各连通；Key 失效自动切换；每类任务可独立绑定 |
| **P0** | 请求级用量与费用明细 + 预算上限 + 失败不扣费 | 计费透明是唯一能立刻建立信任的差异化 | 每笔请求可见模型/token/金额；超额前预警；中断零扣费 |
| **P0** | 上下文装配面板（逐项开关 + token 估算） | 一致性工程的最小可用形态 | 生成前可见"带了什么、多少 token" |
| **P0** | AI 产物审批门（Diff 逐段接受/拒绝/合并）+ 章节快照 | 长篇托付的前提 | AI 改动默认不进正文；可回滚到任一快照 |
| **P1** | 设定库 + 三级大纲 + 角色卡（结构化落库） | 资产沉淀的主体 | 开书向导 5 类产物全部落表而非聊天记录 |
| **P1** | 智能上下文（抽取风格/角色近况/伏笔/关系图） | 对抗窗口爆炸的核心机制 | 不可手改、可自定义提示词、多份按卷区分 |
| **P1** | 文风特征卡（few-shot + 3–6 条可编辑规则 + 试写对比） | 低成本高感知 | 可跳过提炼只用样本；左右 150 字对比可验收 |
| **P1** | 断点续跑 + 任务级幂等 + 预算上限预估 | 消灭"跑一半废了" | 从第 N 步继续，前序步骤不重跑不重复扣费 |
| **P1** | 篇幅长度守护（项目预算 → 卷配额 → 章目标 ±10%） | 三家全缺，长篇作者真实痛点 | 低于下限自动续写、超上限自动收束；配额预警 |
| **P1** | 场景结构模板（短篇/剧本/公众号/小红书/短视频/职场/学术/品牌） | 决定用户盘子大小 | 每模板独立骨架，资产跨模板可复用 |
| **P2** | 一致性体检（人设/设定/伏笔/时间线跨章 + 风险分级） | 依赖图谱与上下文成熟 | 报告定位到章/段并给可执行建议 |
| **P2** | 拆书（结构反哺大纲，不做全文抓取） | 须避开马良的"番茄直连"灰区 | 只拆结构与节奏，用户自备文本 |
| **P2** | 主题系统（视觉 + 排版 + 题材三层） | 高感知但非留存必需 | 换主题即时生效并持久化 |
| **P2** | 移动端"审 Diff + 记灵感 + 朗读" | 依赖桌面审批门先成型 | 手机可逐段接受/拒绝桌面端改动 |
| **P2** | 多人协作 / API / CLI | B 端场景，需先有稳定工程格式 | 两人共编不冲突；CLI 可批量跑章 |

取舍原则只有一条：**P0 全部服务于"敢托付"，P1 服务于"留得住"，P2 服务于"卖得贵"**。任何 P2 功能都不应挤占 P0 的架构决策窗口——尤其是本地工程格式，一旦上线再改就是迁移灾难。

## 八、风险与对策

| 风险 | 具体表现 | 对策 |
|---|---|---|
| **BYOK 导致收入空心化** | 用户全用自带 Key，软件免费收不到钱（FeelFish 已踩：BYOK 免费逼它靠积分变现，而积分正被 BYOK 绕过） | 能力分层：本地/单机/基础 Agent 免费；一致性体检、智能上下文、协作、云同步付费。**卖"编排与检索"，不卖"token 差价"** |
| **本地优先与云同步的冲突** | 多设备并发编辑冲突（FeelFish 只能手工选"本地覆盖云/云覆盖本地"） | 按章节行级合并 + 最后写入者提示 + 冲突保留双版本供人工择一，不做静默覆盖 |
| **一致性能力被质疑"没有实证"** | 竞品都用自测数字（"矛盾率降低 72%"） | 公开可复现基准：同 prompt/模型/章节任务，公开原文、耗时、token、人工返工率；不做自评打分（马良 89 分横评是反面教材） |
| **数据主权承诺反成迁移跳板** | 用户导出后流向竞品 | 接受它：导出包用开放格式但**保留工程语义**（分卷/伏笔线/关系图），竞品无法原样吃下；把"敢让你走"做成品牌资产 |
| **场景铺太宽导致深度不足** | 八个场景都做半成品 | 场景只做"模板 + 骨架"，共用同一套上下文/审批/资产引擎；每季度只深挖一个场景 |
| **合规与内容风险** | 拆书、仿写、AI 率检测都可能触碰平台规则 | 不做第三方全站抓取（避开马良式灰区）；AI 检测只给风险分级与依据，不承诺"过稿"；版权与训练用途首次启动显式声明 |
| **付费意愿低于预期** | 中文写作工具普遍低价（FeelFish ¥0.85/万字） | 不做 token 差价生意；用"整本包干"（如按本计费不限改稿）把不确定性挪走，与按量档并行 |
| **免费档再次变成漏斗断点** | 学 FeelFish 给"5000 字/月"必死 | 免费额度按**任务深度**给：可完整跑完一本 5 万字并体验智能上下文，之后按本/按月收费 |
