# 墨舟 Mozhou

> 一叶墨舟，渡你过万卷长文。

本地优先、自带模型、全场景的桌面 AI 写作工坊。为中文作者做的 Electron 应用：**12 种创作场景 × 16 个题材 × 5 套视觉主题 × 可控篇幅引擎**，把你自己的模型（OpenAI / Anthropic / Gemini / DeepSeek / 通义 / Kimi / 智谱 / 任何 OpenAI 兼容接口）接进一个真正能写完一本书的工作台。

- **不卖次数、不抽成**：填自己的 API Key，请求从你本机直连你填的接口地址，墨舟不经过任何中转服务器。
- **数据在你电脑上**：正文、设定、灵感都是本地 JSON 文件，随时可整目录备份、可读可改。
- **零原生模块**：不需要 SQLite、不需要编译，装完就能跑。

---

## 为什么又要做一个写作工具

我们把 蛙蛙写作 / 马良写作 / FeelFish 三个产品拆了一遍（完整报告见 [docs/竞品分析.md](docs/竞品分析.md)），结论是它们各自都缺一块：

| | 蛙蛙写作 | 马良写作 | FeelFish | **墨舟** |
|---|---|---|---|---|
| 模型归属 | 平台代充、按次计费 | 平台代充 | 平台代充 | **自带 Key，按 token 实价，零抽成** |
| 数据位置 | 云端 | 云端 | 云端 | **本机文件，可备份可迁移** |
| 篇幅控制 | 靠提示词 | 靠提示词 | 靠提示词 | **长度引擎：按整章目标自动补写（默认开启）** |
| 场景覆盖 | 网文为主 | 网文为主 | 小说为主 | **12 场景（含小红书/短视频/公文/学术/儿童）** |
| 文风复刻 | 弱 | 文风分身（亮点） | 弱 | **文风分身：内置 100 位作家库 + 自定义样本→特征→试写** |
| 长篇一致性 | 弱 | 中 | 智能上下文（亮点） | **全书体检：梗概压缩 + 统一审校** |

墨舟不是把三家功能抄一遍，而是把它们的**长板留下、把「平台代充」这个商业模式换掉**——因为你付给平台的溢价，本来可以变成更长的上下文、更多的重写次数。

## 更新日志

### 1.3.1
- **修：全书一致性体检执行完却没有结果**。体检的输出是一串 JSON 问题，默认额度只有 2600 token，装不下提示词要求的 3–12 条，模型写到一半就被硬截断；而解析器只认「已闭合」的对象，正在写的那个被直接丢弃——如果切在第一条中间，结果就是零条。更糟的是这种情况会走到 `setRaw('')`，空字符串在界面上渲染不出任何东西，于是**整页空白、连报错都没有**。现在：① 体检类额度按 JSON 结构的实际开销重新给足；② 被截断的 JSON 会尽力补全把写完的部分救回来；③ 模型一个字都没返回时，明确显示「这次体检没有拿到结果」并说明原因，不再静默。
- **新：体检的建议可以直接采用**。以前「采纳建议」只是展开一段只读文本，还得自己照着改。现在点「采用」会按问题引用的原文片段**定位到具体段落**，只重写这几段，弹出「改前 / 改后」左右对比，可逐段跳过，点「写入正文」才落盘——**其余段落逐字不变**。定位不到时如实说明并拒绝修改，绝不整章重写。
- **全书一致性的问题也能采用，且会跨章统一口径**。这类问题的证据摘自章节梗概、与正文不会一字不差，所以在涉及章节里按相似度找候选段落，并把「推测的段落」明示出来；涉及多章时对比列表按章分组，一次把各章口径改一致。两章都命中同一处矛盾时，不会只改一侧留下新的不一致。
- **修：跨章定位会误改无关章节**。原先只按「证据片段有多少字重合」打分，阈值又低，一段无关正文只要碰巧含几个常见词就能凑够分——例如「亡妻与存活冲突」这条建议会去改两个只提到「急诊留观室」的章节，结果只是被润色一遍，矛盾一点没解决。现在改为按**人名/实词锚点的字符覆盖度**判定，兼看字面重合：只共享地名不再成为目标，真正的矛盾段落仍然命中。体检提到的章节若没找到对应正文，弹窗会明说「体检提到 N 章，其中 M 章没找到对应正文」，不让人误以为全改完了。
- **修：全书体检的问题大量「定位不到具体段落」**。上一个修复收紧过头：它要求证据里的锚点**整串**出现在正文里，可全书体检的证据摘自章节梗概，梗概本身就是转述——「陈屿醒来后把苏念当成了已故的妻子周予安」和正文「陈屿在急诊留观室醒来，把苏念认作亡妻周予安」讲的是同一件事，却没有一个字串能整句对上，于是这类真问题几乎全被拒。现在改成按**字符覆盖度**判断，允许措辞出入；同时仍保留字面重合作为第二道闸，只沾一个地名的无关段落照样进不来。
- **改进：按建议里点名的章节去找**。建议常写着「把第 1 章的 X 改为 Y」，而模型填的 `chapterIds` 可能漏填或填错。现在会从建议、问题描述里把「第 N 章」读出来，优先在这些章里定位——模型亲口指的位置比盲猜可靠。
- **修：只做表面润色也算「改好了」**。模型的常见失败是把段落通顺地重述一遍（diff 非空但矛盾没动）。现在会检查建议里的明确替换（如「把亡妻改为妻子」）是否真的落实，没落实就明确提醒。
- **改进：对比只高亮真正变化的字词**。以前整段划掉，改成只给差异部分标红/标绿，改了两三个字也能一眼看出。
- **修：章节体检偶尔「没能解析成结构化结果」**。根因是模型有时无视「只输出 JSON」的要求，直接回一段分析文字，整份结果因此作废。现在两头都补上：提示词把输出约束提到最高优先级、加上「首字符必须是 {」和完整示例；万一模型还是不听话，就从文字里还原评分与评语（判断不出分数的那一项显示「未评」，绝不凭空编数字）。
- **修：续写字数总是不够**。长度守护此前绑在「严格模式」上，而出厂默认是宽松模式——等于**所有人默认都不守护**，提示词里写着「约 2500 字」，模型写一半也没人管。现在守护默认开启，按**整章**目标统计（不是只看这一次生成），不足 90% 自动补写，最多 3 轮。
- **修：补写越补越铺**。补写轮原来拿「还差多少字」去套按字数的预算公式，撞上 2048 的下限，结果越补给的额度越大、模型越写越收不住。现在按**剩余字数**反推，越接近达标给得越少；单轮毫无进展就提前收尾，不再空转三轮烧钱。
- **修：补写时模型自己续自己**。已写正文原先作为 `assistant` 消息喂回去，模型会顺着自己刚写的结尾继续铺陈，情节反复。现在作为**材料**放进 `user` 消息，并明确要求「只补差额」。
- **修：思考很久，正文一片空白**。推理模型把输出额度全花在思考上、一个字正文都没写时，主进程原先**不报错、静默返回空串**，上层无从判断该不该重试，弹窗还照样写着「生成完成」。现在这种情况会自动重试一次并把额度抬高 50%；仍为空则明确告诉你「额度被思考吃光」，并给出换非推理模型、调大「输出预算 → 正文生成」、调大目标字数三条出路。
- **修：正常结束被当成错误，正文连同最后一帧一起丢**。流式传输把「连接正常关闭」和「出错」混在同一个标志里，正常收尾也走了错误分支，已经收到的正文和最后那个带 `finish_reason` 的帧全部丢失——表现为「写一半就断」或「正文被截断却显示正常」。
- **修：网关不给 `[DONE]` 就断开时，最后一帧被吞**。SSE 解析只按空行切事件，最后一帧若没跟空行，里面带的 `finish_reason: "length"` 就永远读不到，于是被截断的正文被当成完整正文交给作者。
- **修：Anthropic 渠道的截断检测一直失效**。它的 SSE 路径 `return` 时漏了 `finishReason`（只有非流式分支有），导致 Anthropic 渠道永远判断不出「这篇被截断了」。
- **一键开书的首章也接上了长度守护**：此前只调用一次、吐多少算多少，目标 2500 字出来 800 字也没人管。现在补写吃首章自己的预算项。
- **过程可见**：生成结束后会显示「已完成（首轮篇幅不足，自动补写 3 轮…）」，不再一律写「生成完成」把补写过程抹掉；模型只思考不动笔时，会在界面上直接说明原因和解决办法。
- **修：章节状态与大纲状态各说各话**。同一章会在写作台显示「撰写中」、在大纲页显示「已完成」——两边各存一份状态、各改各的。现在统一成一条链：**大纲节点的状态是「计划」，章节的状态是「事实」**，在哪边改另一边立刻同步；正文从空变成有字时「待写」自动转为「撰写中」。老数据里写作 `planned` 的章节状态会在读盘时迁移到 `planning`。
- **修：章节列表的状态是个死徽标**。它此前既不会自动更新（写正文、生成正文都不动它），也没有任何手动入口（是个不可点的 `<span>`），状态实际只由「怎么建的这一章」决定。现在点一下即可在 `待写 → 撰写中 → 已完成` 之间循环。
- **修：大纲页摘要挤掉章节名**。章节行里标题和摘要抢同一个弹性容器，两边都可收缩，摘要一长（AI 生成的章纲动辄上百字）就把标题压没了，看上去像「状态覆盖了章节名」。现在标题固定不被压缩，由摘要承担截断。
- **修：手工新建的章节认不出自己属于大纲哪一节**。章节与大纲节点靠 `outlineNodeId` 关联，但手打章节和 1.3.0 之前的数据里这个字段是空的，导致大纲页明明建过章仍显示「建为章节」，再点一次就是建出同名重复章。现在优先用 `outlineNodeId`，缺失时按去掉序号与标点后的标题兜底匹配（一个节点只归属一章）；写作台新建章节时也会自动挂到对应节点上并落盘。「建为章节」成功后直接跳到写作台那一章。

## 功能

### 写作台
- **12 种场景预设**：长篇小说 / 短篇 / 剧本 / 同人 / 公众号 / 小红书 / 短视频口播 / 品牌文案 / 职场公文 / 学术论文 / 儿童文学 / 自由写作。每种场景自带专属系统提示词、专属快捷动作、默认篇幅与结构层级（长篇是「卷/章」，剧本是「幕/场」）。
- **16 个题材公约**：玄幻 / 仙侠 / 都市 / 悬疑 / 科幻 / 言情 / 历史 / 军事 / 游戏 / 末世 / 无限流 / 系统流 / 现实 / 青春 / 奇幻 / 恐怖。题材决定「读者期待什么」，会被注入每次生成。
- **流式正文生成**：一边生成一边进正文，随时停止。
- **选区动作**：扩写 / 精简 / 改写 / 去 AI 味，加上当前场景的专属动作（如悬疑的「加章末钩子」）。全部以 Diff 方式**替换选中文本**，而不是另起一段。
- **半句续写**：写到半句话卡住时，点「接着这半句」——它读光标所在段落的断点，让模型从这半句接着往下写并落回光标处，而不是一律追加到章末。旁边还有「重写本段」，整段换掉而不是往后加。
- **搜索**：⌘F 打开，可在「本章」与「全书」之间切换，区分大小写可选。结果按章节折叠、命中词高亮并带前后文，点一下就跳到那一章那一处（跨章会先切过去再定位）。搜索只扫正文，不含设定集与大纲。
- **校读**：本地检查半角标点混排、中文字间多余空格、重复词（的的 / 已经已经）与引号配对，不调用模型、不花钱。每条可「采用建议」一键改，也可「忽略」——机器说的话，作者有权不听；忽略记录跨改动保留，换章自动清空。
- **长度引擎**：设定目标字数后，**默认就守护**（不再需要手动开严格模式）。按整章口径统计，不足 90% 自动补写，最多 3 轮；补写预算随剩余字数递减，越接近达标给得越少，不会越补越铺。写正文时若模型只思考没动笔（推理模型把额度花在思考上），自动重试一次并抬高额度；仍为空会直接告诉你换模型或调预算，而不是丢一片空白。顶部实时显示「本章 / 目标 / 进度」。
- **Tiptap 编辑器**：标题、引用、列表、高亮、对齐、撤销重做；专注模式、打字机滚动、非焦点段落淡出。

### 结构与设定
- **大纲**：卷/章两级树，行内改名、状态轮转、上下移动、拖入；AI 生成整卷章纲后逐行编辑再落库；章节可「建为章节」直接开写。
- **设定集（World Bible）**：角色卡（外貌/性格/动机/缺陷/人物弧光/说话方式/人物关系/对 AI 隐藏）、世界观条目（7 类，可逐条对 AI 隐藏——写反转时特别有用）、术语表、时间线、伏笔台账（主线/支线 × 未回收/已回收）。
- **灵感箱**：随手记录、置顶、AI 抽卡出 5 条可直接开写的桥段。

### 三个「不同」
1. **不同场景**不只是换提示词：结构层级、快捷动作、默认篇幅、审核标准都跟着场景变。
2. **不同主题**是双层的：视觉主题（纸白/午夜/仿古/薄雾/深林 5 套，全部 CSS 变量驱动）＋ 题材公约（内容层的「主题」）。
3. **不同篇幅**由长度引擎管：不是写一句「请写 3000 字」就完事，而是生成后校验、不足则续、超了则收。

### AI 能力
- **一键开书**：一句话灵感 → 书名简介 → 核心设定 → 分卷大纲 → 首卷章纲 → 首章正文，五步流水线，每步产物可编辑可重跑。
- **文风分身库（100 位作家）**：内置传统文学、网文金牌、言情女性向、悬疑科幻、历史武侠、新类型六大流派共 100 位作者的文风分身，每位 6–8 条可执行特征。书内搜索引用即可用，改一处全库同步；支持分类、标签、多词搜索、AI 辅助新建/改写、恢复出厂。
- **自定义文风分身**：喂 1–5 段自己的文字（≤5000 字）→ AI 提炼 3–6 条**可执行的**文风规则 → 双栏对比试写（带分身 vs 不带分身），满意再绑定本书。
- **全书体检**：先把每章压成梗概（复用已写摘要），再把角色卡 + 世界观 + 时间线 + 伏笔 + 全部梗概一起审，输出带章节定位的问题卡（人物/时间线/设定/伏笔/逻辑），点一下就跳到那一章。
- **章节体检**：节奏 / 冲突 / 悬念 / 注水 四项评分 + 具体问题。
- **段落侧批**：以编辑视角把一章读一遍，把批注挂在对应段落旁边（删 / 改 / 慢 / 快 / 虚 / 偏），**只批注、不改稿**，正文一个字都不动。
- **伏笔盘点**：本地台账 + AI 找出「正文里有、台账里没有」的悬念，一键登记。
- **上下文面板**：实时显示这次请求到底喂了什么、每块多少 token、超预算时哪块被裁掉了——不做黑箱。

### 模型与渠道
- **12 个内置厂商预设**：OpenAI、Anthropic、Gemini、DeepSeek、通义千问、Kimi、智谱、SiliconFlow、OpenRouter、火山方舟、Ollama、自定义。
- **三种协议**：OpenAI 兼容 / Anthropic Messages / Gemini generateContent，各自的流式格式、system 位置、参数名差异都在适配器里抹平。
- **任意自定义渠道**：BaseURL + Key + 自定义 Header（有些中转要 `HTTP-Referer` 之类）+ 模型列表，可「从接口拉取」真实模型列表。
- **任务级模型路由**：正文 / 大纲 / 润色 / 起名 / 摘要 / 体检 / 对话 七个任务可以各用不同模型——正文用便宜的快模型，大纲和体检用贵的强模型。
- **Key 加密存储**：走系统钥匙串（Electron `safeStorage`，macOS 上是 Keychain），明文不落盘。
- **费用透明**：每个模型可填输入/输出单价，统计页按实际 token 本地估算花费。

### 数据与导出
- **本地 JSON**：`项目/作品/项目.json`，一次写入走「临时文件 → rename」，并保留 `.bak`，断电不毁稿。
- **章节历史**：每次改动正文前自动留一份快照，每章最多 20 份（一分钟内的连续编辑合成一份，长会话不会把位置吃满）。章节列表出现历史图标，可预览并还原到任一版本；还原本身也会进快照，所以还原也能撤销。
- **备份可见**：设置页有「你的稿子现在有几份」，把当前稿、历史快照、`.bak`、手动导出的备份四层摊开写清楚——不替你上云，就得让你知道备份到底在哪。
- **备份 / 还原**：一键导出全部作品，一键从备份目录还原。
- **导入**：TXT / Markdown 自动按「第 N 章」分割成章节。
- **导出**：Markdown / 纯文本 / Word(.docx) / PDF / 独立 HTML。DOCX 是真正排版过的（宋体 12pt、1.5 倍行距、首行缩进 2 字符、章节分页、引用框线），不是把 HTML 塞进去。

## 快速开始

### 环境
- Node.js ≥ 20
- macOS 12+ / Windows 10+（Linux 未测试）

### 开发运行

```bash
npm install
npm run dev
```

### 类型检查与构建

```bash
npm run typecheck     # tsc --noEmit
npm run build         # electron-vite build → out/
```

### 打包

```bash
npm run dist:mac      # → release/Mozhou-1.3.1-arm64.dmg + -x64.dmg
npm run dist:win      # → release/Mozhou-Setup-1.3.1.exe
npm run dist:dir      # 只出未压缩目录，调试打包问题用
```

本仓库已附带可直接运行的产物：

| 产物 | 说明 |
|---|---|
| `release/Mozhou-1.3.1-arm64.zip` | Apple Silicon 版，解压得到 `Mozhou.app`，拖进「应用程序」即可 |
| `release/Mozhou-1.3.1-x64.zip` | Intel 版 |
| `release/mac-arm64/Mozhou.app` | 解包后的 arm64 应用本体 |

> **关于 .dmg**：制作 dmg 要调 `hdiutil` 挂载磁盘镜像。在受限沙箱/CI 容器里这一步会被系统拒绝（`hdiutil create: Operation not permitted`），所以这里交付的是等价的 `.zip`。在你自己的 Mac 桌面上运行 `bash scripts/make-dmg.sh`（或 `npm run dist:mac`）就能得到 dmg——`electron-builder.yml` 里的 dmg target 一直是配好的，没有删。

> 首次打包需要下载 Electron 预编译包（约 100 MB），electron-builder 会缓存在 `~/Library/Caches/electron-builder`。国内网络建议先设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。

### 本地验收（可选）

仓库里带了一个不进入产品包的演示数据生成器与截图脚本：

```bash
npm run seed                                  # 生成 .testdata/（含一部 3 章的演示长篇 + 一部短篇）
node scripts/shot.cjs shots/ws.png "__MZ.openProject('p_demo')"
node scripts/mock-openai.cjs                  # 本地假 OpenAI 网关（:8787），验收流式链路
node scripts/test-ai-timeouts.cjs             # AI 超时回归：思考/心跳/非流式网关都要能正常收完
```

> `test-ai-timeouts.cjs` 用假网关覆盖四种慢响应：模型只吐 `reasoning_content`、网关只发心跳注释、网关无视 `stream:true` 一次性返回 JSON、以及真的断流。前三种必须成功收完正文，最后一种必须在空闲上限后中止。

## 技术选型

| 层 | 选择 | 为什么 |
|---|---|---|
| 壳 | Electron 45 | 三端一致、`safeStorage`/`printToPDF` 开箱可用 |
| 构建 | electron-vite 6 + Vite 7 | 主/预加载/渲染三份构建，HMR 快 |
| UI | React 19 + TypeScript 5.9（strict） | — |
| 样式 | Tailwind 4 + CSS 变量主题 | 主题切换只换变量，组件零改动 |
| 状态 | Zustand 5 | 无 Provider 嵌套，`getState()` 方便非组件逻辑读写 |
| 编辑器 | Tiptap 3（ProseMirror） | 结构化文档，选区/替换/Diff 都靠它 |
| 存储 | 本地 JSON + 原子写 | 避开 SQLite 原生模块的编译与签名风险 |
| 导出 | docx 9 + turndown + `printToPDF` | 不依赖 LibreOffice / pandoc |
| 打包 | electron-builder 26 | dmg / nsis 双端 |

**安全边界**：渲染进程 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；文件系统与网络全部在主进程，通过 preload 的 `contextBridge` 暴露一份白名单 API（`window.mz`）；外链一律 `shell.openExternal`，页面内不允许导航到外部 URL。

## 已知限制

- **未做代码签名 / 公证**（没有 Apple Developer ID）。首次打开需要右键 → 打开；分发给他人在 Gatekeeper 下也会提示一次。
- 打包产物默认是 `.zip`（`.app` 已打好、可直接运行）。`.dmg` 的生成需要 `hdiutil` 挂载磁盘镜像，在受限沙箱里会被拒绝，请在本机运行 `bash scripts/make-dmg.sh`。
- Windows 安装包（NSIS）配置已就绪，但在 macOS 上交叉构建需要 wine；建议在 Windows 机器上 `npm run dist:win`。
- 只做了 macOS 与 Windows 打包配置，Linux 未验证。
- 单部作品没有做分卷式的数据库索引，超大项目（>100 万字）打开会略慢（整文件读入内存）。
- 版本快照是「每章 20 个整章副本」，不吃内存但会占磁盘，超大项目可在章节历史里手动清空。
- AI 输出质量取决于你选的模型；本地小模型（7B 级）在长上下文下会明显退化，建议正文用 32B 以上或云端模型。
- 没有做多人协作与云同步——这是设计选择，不是待办。
